## 2. `shared/labels.json` schema

```json
{ "version": 1, "sdi": 0,
  "labels": [ { "label": "324", "tag": "PITCH", "unit": "deg",
                "lsbPerBit": 0.0439453125, "lsbNote": "...",
                "min": -180, "max": 180,
                "display": { "min": -20, "max": 20, "visible": true } } ] }
```

| Label | Tag | Unit | LSB | Range | Display default |
|---|---|---|---|---|---|
| 324 | PITCH | deg | 180/4096 | ±180 | ±20 |
| 325 | ROLL | deg | 180/4096 | ±180 | ±45 |
| 314 | HEADING | deg | 180/4096 | 0..360 | 0..360 |
| 204 | BARO_ALT | ft | 4 | −1000..100000 | −1000..45000 |
| 206 | CAS | kt | 0.125 | 0..600 | 0..250 |
| 212 | VERT_SPEED | ft/min | 1 | ±32000 | ±6000 |

- Labels are **octal strings**, unique. Tags are `UPPER_SNAKE`, unique.
- `max / lsbPerBit` must fit 19 bits (≤ 524287).
- `display` window must sit inside `min..max`, with `min < max`.
- `test/a429.test.mjs` "label table matches the agreed contract" pins the six
  labels. Adding a label means updating that test (backend agent).

## 3. Changing a contract

A contract is anything two layers both depend on:

| Contract | Producers / consumers |
|---|---|
| `shared/labels.json` | backend (runtime), firmware `flight.h` (by hand), frontend (tags), tests |
| A429 word encoding | `firmware/src/a429.h`, `backend/src/a429/codec.js`, vectors |
| Pad frame (17 bytes) | `host/pad-reader.ps1`, `host/keyboard-reader.ps1`, `firmware/src/pad.h`, `tools/test-pad-path.mjs`, `tools/demo-inject.mjs` |
| SSE / REST shapes | `backend/src/server.js`, `state.js`, `config.js`, `frontend/js/*.js`, e2e tests |
| Ports 8090 / 5555 / 5556 | `backend/serve.mjs`, `tools/run-all.mjs`, `host/pad-reader.ps1`, docs |

Procedure:

1. Write the change as a short spec: old shape, new shape, every file affected.
2. Check it against the decisions in `rules/common.md` §3. If it reopens one,
   stop and ask the user.
3. Edit `shared/` yourself. Hand each layer its task with the spec.
4. Land all layers together. A half-applied contract change is never committed.
5. Regenerate vectors if encoding or labels changed: `node tools/gen-vectors.mjs`.
6. Run the full verification (§6).

## 4. Golden vectors

- `tools/gen-vectors.mjs` derives every word twice: with `codec.js` and with an
  independent `handEncode()`, and asserts they match. Never hand-edit the JSON.
- Fields per vector: `name, label, sdi, magnitude, ssm, labelOct, word, wordHex, bytesLE`.

## 5. Tools

| Tool | Purpose |
|---|---|
| `start.mjs [mode]`, `start.cmd` | Friendly launcher: menu, prerequisite check, gamepad detection, waits for data, opens the SFD, prints controls. Closes an old session still running on 8090 first, so the menu always shows; `stop` only stops it. Wraps `run-all.mjs`. `npm start`, `npm run stop` |
| `run-all.mjs [--keyboard\|--demo\|--no-pad\|--replay]` | Start the input source, QEMU and backend in order; Ctrl+C tears down. Input: gamepad (default), keyboard, scripted demo, none, or replay (backend only) |
| `test-pad-path.mjs` | 17 checks: synthetic pad frames → firmware → A429 → backend, incl. rate commands, hold on centre, D-pad step, NCD freeze, B long press |
| `test-keyboard-path.mjs` | 10 checks: the real `host/keyboard-reader.ps1` (keys simulated with `-Hold`) → firmware → A429 → decode. Windows only |
| `verify-pad-live.mjs` | Real pad through the real pipeline, live table |
| `probe-rate.mjs <s>` | Runs QEMU on port 5555 and measures frame rate; expect ≈ 50 Hz. Assumes 24 bytes/frame and a 12-byte banner |
| `capture.mjs [s] [out]` | Runs QEMU on port 5570 and records UART0 (default `shared/capture.a429`) |
| `decode-capture.mjs <file>` | Decode a capture offline |
| `gen-vectors.mjs` | Regenerate golden vectors |
| `demo-inject.mjs <s>` | Scripted bank-and-climb in place of the pad; `run-all --demo` starts it |
| `probe-hid-axes.mjs` | Inspect HID axes |
| `chain.mjs` | Run chain: stage status, next stage, agent briefs (`run-chain` skill) |
| `check-ai.mjs [--write]` | Framework vs code: ownership, agents, skills, wrappers, paths, labels, ports, counts |
| `check-ownership.mjs` | Owner of each changed file; `--agent` fails on files outside its paths |

Run tools from the repo root: several use relative paths (`shared/labels.json`,
`firmware/build/firmware-main.elf`). QEMU-based tools need the firmware built first.

`run-all.mjs` start order matters: QEMU's UART1 and UART0 are TCP **clients**, so the
pad reader (5556) and backend (5555) must listen first. Wait for the pad reader's
printed ready line; never probe port 5556 (it accepts exactly one client).

## 6. Full verification (before any merge to `sandbox`)

```bash
node tools/chain.mjs --all         # every stage; see the run-chain skill
node tools/check-ownership.mjs --base sandbox
```

`--all --hw` adds M3 (real gamepad). MANUAL stages still need a person to look at
the pages. Report each stage; name every SKIP and why. If the toolchain is absent
locally, the CI run for the branch is the evidence for M2 and M7.

### CI (`.github/workflows/ci.yml`)

| Job | Runs |
|---|---|
| framework | `node tools/check-ai.mjs`, ownership report for the push or PR |
| test | `npm test`, chain stages M1, M4, M5, M6 |
| firmware | apt `gcc-arm-none-eabi` + `qemu-system-arm`, `ARM_TOOLCHAIN_BIN=/usr/bin`, chain M0, M2, M7 |

M7 measures real time on a shared runner; if it is flaky there, report it, do not
loosen the expectation silently.

### Framework upkeep

- `.claude/` is generated: edit `ai/agents/` or `ai/skills/`, then
  `node tools/check-ai.mjs --write`.
- A new agent needs an entry in `ai/ownership.json` and a file in `ai/agents/`.
- A new skill needs `ai/skills/<name>/SKILL.md` with matching `name`.
- Facts that `check-ai.mjs` cross-checks: label tables, ports, pad frame length,
  `STALE_MS`, SSE rate, `RATE_HZ`, deadzone, test count, every backticked path in
  `ai/` and `AGENTS.md`. Add a fact there when a rule starts restating a new one.

## 7. Documentation

- Docs state facts that were measured. Keep the "measured, not assumed" tone.
- When a decision is taken with the user, record it in `docs/PLAN.md` with the date.
- When a fact in `ai/rules/` changes, update the rule in the same commit.
- New stale statements go in `rules/common.md` §8 until fixed.

## 8. Coordinating agents

- Split work by ownership (`rules/common.md` §1). One task per agent, with: goal,
  files, contract spec if any, verification command, done condition.
- Run independent layer tasks in parallel. Run dependent ones in order:
  contract → backend → frontend, contract → embedded.
- Review each layer's result against its rule file before integrating.
- Integrate on the feature branch. Only the user decides merges to `sandbox`.
